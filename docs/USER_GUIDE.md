# AI 赋能项目使用手册

> 适用对象：项目成员、项目经理、知识运营人员、项目管理员、离职人员与接替人<br>
> 适用版本：PRD v1.1.54 及当前仓库基线<br>
> 更新日期：2026-09-22

本手册用于帮助用户正确完成知识沉淀、知识问答、新人赋能、知识治理、飞书知识自动化和离职交接。技术部署、API 和数据库维护细节请参阅项目根目录的 `README.md`。

## 1. 使用前先了解三件事

1. **必须通过服务地址访问。** 使用 `http://localhost:8000` 或管理员提供的地址，不要直接打开 `frontend/index.html`，也不要使用 `file://` 页面。
2. **系统按权限使用知识。** 看不到某份资料或问不到某项内容，不一定是故障，也可能是该知识未生效、已撤销、正在处理，或当前账号没有来源访问权限。
3. **耗时操作在后台执行。** 文档解析、OCR、向量索引、图谱重建和飞书同步会生成“处理任务”。提交成功后应查看任务状态，不要反复上传或重复点击。

## 2. 快速登录

### 2.1 已部署环境的普通用户

1. 向项目管理员确认访问地址和自己的企业邮箱账号。
2. 在浏览器打开系统地址。
3. 输入企业邮箱和密码。
4. 登录后先确认左侧导航、右下角服务状态和页面数据是否符合自己的角色权限。

如果页面提示“账号尚未激活或已停用”，请联系项目管理员检查成员状态。普通用户无法自行绕过激活或停用状态。

### 2.2 本地演示环境

本地比赛演示可由管理员在根目录 `.env` 中设置：

```ini
DEMO_SIMPLE_AUTH=true
```

启用后，**已经写入当前本地 SQLite 的项目成员**会自动激活，密码为企业邮箱 `@` 前缀。例如：

```text
邮箱：demo-member@example.com
密码：demo-member
```

注意：

- Git 仓库不会上传 `.env`、`data/app.db`、邀请文件或真实密码。
- 全新克隆的项目不会自动拥有原演示机上的成员账号，管理员需要先创建成员。
- 演示认证是弱认证，只能用于受控演示，不能用于正式环境或互联网公开部署。

### 2.3 正式环境

正式环境必须设置：

```ini
DEMO_SIMPLE_AUTH=false
```

管理员创建成员并生成一次性激活文件后，用户通过激活流程设置强密码。连续 5 次登录失败会锁定 15 分钟；如果忘记密码或账号被停用，请联系项目管理员处理。

## 3. 角色与权限

| 角色 | 主要工作 | 不能默认执行的操作 |
|---|---|---|
| 项目成员 `project_member` | 查询授权知识、上传普通资料、完成学习任务、提交本人交接 | 管理成员、系统密钥、全项目知识发布 |
| 知识运营 `knowledge_operator` | 分类、审核、发布、复审、图谱维护、知识任务验收 | 管理系统密钥和成员账号 |
| 项目经理 `project_manager` | 管理项目知识、飞书采集、学习计划和离职交接 | 管理系统密钥和成员账号 |
| 项目管理员 `project_admin` | 成员、配置、飞书、知识生命周期、数据治理和交接管理 | 不能绕过来源 ACL 阅读未授权正文 |

权限原则：

- 页面按钮只是操作提示，最终权限由服务端校验。
- 管理角色不等于能够阅读所有私有资料。
- RAG、知识图谱、新人赋能和 Agent 都继承原始来源权限。
- 调整成员角色或来源权限后，用户应刷新页面；被停用成员的会话会失效。

| 知识库 | 所有成员、知识运营 | 上传、预览、分类、审核和维护知识 | 可检索的统一知识资产 |
| 知识图谱 | 所有成员、知识运营 | 查看知识主题和关系 | 可视化知识网络 |
| 新人赋能 | 新成员、负责人、项目经理 | 按岗位学习和补齐知识 | 学习计划、进度和缺口 |
| 知识任务 | 责任人、验收人、治理角色 | 处理知识缺口、复审和交接补充 | 有证据、可验收的改进任务 |

| 系统设置 | 项目管理员及部分治理角色 | 配置模型、成员、飞书和数据治理 | 可运行、可审计的项目环境 |

## 5. 推荐的完整业务闭环

日常使用建议遵循以下路径：

```text
文档 / 飞书消息 / 交接资料
        ↓
解析、OCR、安全检查与后台处理
        ↓
知识资产审核、生效和版本管理
        ↓
RAG 问答、知识图谱、岗位知识地图
        ↓
发现知识缺口、过期内容或交接风险
        ↓
知识任务分派、补充、证据和验收
        ↓
更新知识资产并继续服务团队
```

知识发布、撤销或失效后，问答、图谱和新人赋能应使用同一份当前事实。不要在多个页面重复创建内容来“修正”结果，应维护原知识资产或处理对应知识任务。

## 6. 知识库操作

### 6.1 上传新知识

1. 打开“知识库”。
2. 点击“选择文件”或拖入文件。
3. 选择分类；无法判断时可保留自动分类。
4. 提交上传。
5. 系统受理后进入“处理任务”查看解析、OCR、索引和投影进度。
6. 任务完成后返回知识库，确认资产状态、分类、知识块数量和预览内容。

支持的常用格式包括 PDF、TXT、MD、DOCX、CSV、JSON、PNG、JPG、JPEG 和 WebP。默认单批最多 20 个文件、总计 100 MB；每个文件拥有独立任务，单项失败不会阻断整批。

界面中的分类统一使用中文业务名称。“内置分类”是系统自动归类、RAG 和图谱关联的稳定分类，不能在界面直接改名或删除；用户自建的中文分类仍可编辑和删除。

### 6.2 更新已有知识

更新已有资产时使用该资产的更新入口，并只上传一个新版本。不要把同一资料反复作为“新文档”上传，否则会增加重复治理成本。

新版本只有在解析和向量写入成功后才能替换当前生效版本。处理失败时，旧的有效版本仍继续服务，错误会显示在处理任务中。

### 6.3 正确理解资产状态

| 状态 | 含义 | 是否参与问答/图谱/新人赋能 |
|---|---|---|
| 草稿 | 内容已保存但尚未进入审核 | 否 |
| 待审核 | 已提交治理人员确认 | 否 |
| 已生效 | 当前可用的权威版本 | 是，但仍受权限限制 |
| 待复审 | 到达复审时间，需要确认是否继续有效 | 按当前生命周期规则处理 |
| 已失效 | 已过期或被判定不再适用 | 否 |
| 已撤销 | 主动停止使用，但保留来源和审计证据 | 否 |
| 处理失败 | 解析、OCR、索引或投影未完成 | 否，应进入处理任务修复 |

“撤销”不是物理删除。撤销记录用于追溯，不参与当前知识数量、RAG、图谱和新人赋能。只有符合数据治理规则并经过影响预演和确认，才能执行永久删除。

永久删除后的同名文件可以再次上传。系统会为它创建新的来源、资产和版本身份，旧删除墓碑继续保留用于审计，不会被恢复为当前知识。

### 6.4 预览与质量检查

发布前至少检查：

- 标题、分类和责任人是否正确。
- 文本是否完整，表格或扫描页是否被正确解析。
- 图片 OCR 是否提取到有意义内容。
- 是否包含密码、密钥、个人隐私或无权扩散的信息。
- 来源、版本和引用是否能够追溯。

## 7. 知识问答

### 7.1 提问方式

1. 打开“知识问答”。
2. 保持“RAG 检索”开启，以便答案使用项目知识并附加引用。
3. 输入一个具体、可验证的问题，例如“当前交接流程有哪些完成条件？”。
4. 选择需要的模式并发送。
5. 查看检索、匹配、生成和引用状态，以及回答下方的来源。

高质量问题通常包含对象、时间、范围和期望结果。避免只输入“介绍一下”“怎么办”等缺少上下文的问题。

### 7.2 如何判断答案可信

- 优先查看引用是否来自正确资产和版本。
- 重要结论应打开来源预览核对原文。
- “当前知识不足”是正常的安全结果，不应要求模型猜测。
- 如果答案无帮助，提交原因；系统可把反馈转为知识改进任务。
- 涉及删除、发布、权限、审批或对外发送的信息，必须人工确认后再执行。

### 7.3 没有答案时怎么处理

依次检查：

1. 资料是否已上传且处理任务已完成。
2. 资产是否为“已生效”。
3. 当前账号是否有来源权限。
4. 提问是否过于宽泛或使用了资料中不存在的简称。
5. 引用不足是否已经形成知识任务。

不要通过关闭权限校验或要求模型编造答案来解决知识缺口。

## 8. 知识图谱

知识图谱只展示当前账号有权访问的已生效知识。进入页面时系统默认适配全部节点到可视区域。

图谱节点表示文档中的“知识主题片段”，不是文档文件本身，因此节点数通常多于文档数。长文档会拆分出多个主题节点；范围筛选和图例显示中文业务分类，内部分类编码不会要求用户理解。

常用操作：

- 拖动空白区域平移视图，滚轮缩放。
- 点击节点查看来源和关联知识。
- 使用“适配全部”恢复全局视图。
- 治理人员调整关系后保存，普通浏览不会改写图谱。
- 文档发布、撤销、删除或修复后，等待对应处理任务完成再刷新图谱。
- 旧文档仍只显示一个节点时，由知识运营人员点击“重新构建图谱”，系统会兼容拆分历史长知识块，无需重新上传文件。

如果知识库已有资产但图谱显示 0 节点，先确认资产是否已生效，再到“处理任务”检查图谱投影或启动自检修复是否仍在排队、失败或等待重试。

## 9. 新人赋能

### 9.1 项目经理或负责人

1. 在“新人赋能”中维护岗位模板。
2. 为岗位设置必需知识主题、权重、上手重点、实践任务、完成标准、负责人和指定必读资料。
3. 选择目标成员和岗位并创建学习计划。
4. 分配后，在“进行中学习计划”列表集中查看由自己负责确认的成员；每一行显示成员、岗位、个人进度、目标完成日期、待补资料数和负责人确认条件。点击成员后才查看完整任务和证据。
5. 只有阅读与实践任务全部完成后，“负责人确认”才会启用。确认前请核对任务证据；确认操作会记录确认人、时间与依据，完成的计划会退出主管待办列表。
6. 检查目标成员对指定资料是否有访问权限。
7. 对缺失主题创建或接收系统生成的知识任务。

项目知识就绪度按主题覆盖 50%、权威性 20%、新鲜度 20%、可追溯性 10% 计算；它衡量的是项目是否准备好支持该岗位，不等于个人已经完成学习。

### 9.2 新成员

1. 打开分配给自己的学习计划。
2. 按优先级阅读必读资料。
3. 完成实践任务并提交真实证据。
4. 等待负责人确认。
5. 发现资料缺失、过期或无权访问时反馈缺口，不要虚假标记完成。

个人上手进度按必读完成 60%、实践任务 25%、负责人确认 15% 计算。无权访问或缺少资料的任务会被阻断，这是权限和质量保护，不是页面故障。

出现“被阻断”时按以下顺序处理：

1. 查看主题名称，确认知识库中是否已有对应分类且状态为“已生效”的资料。
2. 如果刚上传、重新上传或发布资料，等待对应处理任务完成。
3. 点击学习计划右上角“刷新学习资料”。系统只会匹配该成员本人有权访问的当前有效资料。
4. 仍显示阻断时，说明当前权限范围内确实没有匹配资料，应完成对应知识补充任务或联系知识运营人员调整分类、权限与有效状态。

系统也会在知识发布、投影修复和服务启动时自动刷新进行中的计划。刷新不会清除已完成任务或实践证据，也不会把已撤销、已删除资料重新加入计划。

## 10. 知识任务

知识任务用于把“发现问题”转成责任明确、可验证的改进动作。任务可能来自新人知识缺口、问答负面反馈、飞书异常、资产发布/复审、责任人离职或交接补充。

推荐处理顺序：

1. 查看任务类型、优先级、来源、负责人和截止时间。
2. 领取或由治理角色分派任务。
3. 点击“开始处理”，填写处理说明。
4. 补充知识、修正文档或解决关联业务问题。
5. 需要补充文件时，在“完成证据”下点击“上传任务资料”。该入口与知识库的“新建知识”使用同一套分类、格式和批量上传规则；每个文件都会创建独立处理任务。任务资料只能新建知识，不提供“更新现有知识”。
6. 上传受理后，文件名会以“知识库处理中”自动写入完成证据。到“处理任务”确认所有文件入库成功后，再提交证据和完成说明；不要把“已受理”误当作“已入库”。
7. 由独立验收人通过或退回。

对于新人岗位知识缺口，上传文件本身不等于任务完成：文件需要处理成功并形成当前生效知识资产，分类必须与缺口主题一致，且任务负责人必须有权访问。满足这些条件后，系统会自动关联精确资产和版本，把任务从“待处理/处理中”推进到“待验收”；报告人或任务管理人员验收后才会完成。

系统已经匹配到生效资料并把任务推进到“待验收”后，不需要再点击“开始处理”。此时应核对关联资料并执行验收；“开始处理”只用于尚未找到有效资料、仍处于“待处理”的任务。

如果“开始处理”不可用，任务详情会显示具体原因。常见情况包括当前账号不是负责人、任务已经进入待验收，或任务状态已变化。任务负责人或任务管理人员在“待处理”状态应可以开始处理；不要通过反复上传文件来绕过权限或验收。

任务负责人不能验收自己的任务。如果当前账号同时是负责人和任务管理人员，请先在“任务负责人”中选择其他项目成员并点击“转派”，由对方复核资料；原报告人或任务管理人员随后点击“验收通过”。转派不会清除系统已匹配的资料和完成证据。

任务不能随意物理删除。创建错误或不再需要时，具有权限的用户点击“取消任务”，在确认弹窗中填写取消原因。取消后保留操作记录，用于避免同一问题被重复创建和满足审计要求。

如果“取消任务”不可点击，请检查：

- 是否已选择一条未结束任务。
- 当前账号是否为任务本人或治理角色。
- 是否已填写取消原因。
- 任务是否已完成、已验收或已取消。

## 11. 处理任务

处理任务记录后台工作的真实状态，常见任务包括文档上传、OCR、图谱重建、资产投影修复、飞书历史同步、候选批处理、备份和数据清理。

任务列表优先显示文档名、消息来源或业务操作名；任务 ID 只在右侧详情中用于管理员诊断。可以使用文档名称搜索任务。

| 状态 | 用户应做什么 |
|---|---|
| 排队中 | 等待执行，不要重复提交 |
| 运行中 | 查看阶段和进度，必要时可请求取消 |
| 等待重试 | 系统会按策略重试，可先查看错误摘要 |
| 已完成 | 返回业务页面确认最终结果 |
| 部分完成 | 查看逐项结果，修复失败项，不要重做成功项 |
| 失败 | 任务发起人修复文件或等待管理员修复环境后可重试本人任务；治理角色可重试项目任务 |
| 已取消 | 已完成的逐项结果可能保留，重新操作前先核对业务页面 |

服务重启后任务状态不会丢失。失败任务会按当前用户权限显示“重新执行”：发起人可恢复自己的任务，治理角色可恢复项目任务。错误详情会隐藏密钥等敏感信息；需要进一步诊断时请记录任务 ID 交给管理员。

## 12. 飞书集成

### 12.1 管理员首次配置

1. 在“系统设置”或“飞书集成 / 设置与审计”保存 App ID 和 App Secret。
2. 在飞书开放平台启用机器人能力和事件通道。
3. 根据页面检测结果申请消息、资源下载和 OCR 等必要权限。
4. 检查长连接或事件回调状态。
5. 发现群聊后，将群显式绑定到当前项目并设置采集规则。
6. 先用测试群发送一条文本、一张图片和一条富文本进行验证。

不要因为机器人“已连接”就认定全部能力可用。历史消息、外部群、云文档或附件正文受飞书接口和真实授权限制，应以页面验证结果为准。

### 12.2 日常知识沉淀

1. 授权群消息进入系统后先归档。
2. 系统执行内容评估、线程聚合、去重和安全判断。
3. 高价值内容形成知识候选或按规则自动入库。
4. 异常、低置信度或敏感内容进入“需处理”。
5. 在“内容中心”预览原消息、聚合结果和已形成知识。
6. 已形成知识需要撤销时，从当前知识资产执行撤销，不要删除原始审计记录。

图片和富文本会按“本地 RapidOCR → 飞书 OCR → 兼容多模态模型”依次尝试识别。全部失败时原件仍保留，并显示为“需处理”；安装依赖或修复权限后可从处理任务重试。

### 12.3 在群中使用机器人

- 在授权群中 `@机器人` 后输入明确问题。
- 机器人只能基于当前项目和来源权限回答。
- 需要保存讨论成果时，使用团队约定的知识沉淀表达或由系统自动评估，不必逐条人工确认普通闲聊。
- 机器人没有引用或提示知识不足时，应补充资料或创建任务，不应把回复直接当作正式决策。

## 13. 离职交接

离职交接不是单纯上传文件，而是知识责任和风险的正式转移。

1. 发起交接并选择离职人员、岗位、接替人和计划完成日期。离职人员姓名与职能由系统按当前登录身份自动填入，职能为只读，取自本人账号资料（由管理员在系统设置的“项目成员与权限”维护）；如需变更职能，请先联系管理员修改，再发起交接。
2. 上传交接资料并确认已形成可追溯知识资产。
3. 审阅系统自动盘点的关联资产、未完成任务和图谱主题。
4. 补齐 8 项通用清单及岗位模板追加项。
5. 离职人员逐项提交，接替人逐项接收或退回。
6. 退回项会生成或合并交接补充任务，默认负责人是离职人员；也可在交接列表点“发起补充任务”手动发起，负责人同样默认取离职人员（未匹配到成员时保持未指派，可手动改选）。接替人负责核对并验收补充结果。
7. 风险由离职人员或风险责任人登记等级、影响、责任人、期限、缓解措施，并提交关闭证据；接替人或交接管理人员核对后确认关闭，必要时填写原因重开。
8. 接替人确认后，系统按其权限创建或复用新人学习计划。
9. 五个完成 Gate 全部满足后，由管理角色封存不可变快照。

页面进度达到 100% 不一定代表允许关闭。盘点未审阅、清单未验收、风险未关闭、接替人未确认或学习计划未就绪，都会阻断封存。

交接清单按“待办优先”展示：顶部“待我处理”汇总你当前需要动作的事项（盘点待审阅、已被退回、待你验收、待你提交、阻断风险、待确认关闭），点击可定位并展开对应分组。分组和条目只默认展开含待办的内容，已验收、已处理、已关闭的记录折叠为“已处理/已验收/已关闭 N 项”摘要，标题上常显待办计数；盘点的“说明并排除”输入和风险登记表单需要点击后才展开。

风险闭环由两方分别完成：离职人员或风险责任人负责登记风险、更新缓解措施并提交关闭证据，页面标注为“责任人操作”；接替人或交接管理人员负责核对后确认关闭或重开，页面标注为“接替人操作”。任何一方都不能既登记又自行确认闭环。

必交项提交后由接替人验收。提交人和离职人员即使是项目管理员，也不能审核自己交出的资料，页面显示“等待{接替人姓名}验收”。其他交接管理人员可以代验收或代退回，但必须填写代验收原因；退回时还需填写具体补充要求。审核人、时间和代验收原因会保存，重新提交后的本轮记录重新计算，历史审核记录仍可审计。

### 13.1 提交必交项资料

1. 打开待处理或被退回的清单项，点击“关联已有资料”。选择器只会展示你和接替人都能读取的当前有效资料。
2. 选择资料并点击“关联”。可关联多份，单项最多 10 份；误选可在草稿资料列表中移除。
3. 没有合适资料时，点击“上传补充文件”。支持 PDF、图片、TXT、MD、DOCX、CSV 和 JSON；文件成功入库后会自动关联到当前项草稿。
4. 需要时填写“补充说明（可选）”，例如资料对应章节、交接背景或验证结论。不要填写密码、密钥或令牌。
5. 系统会在输入后自动保存草稿，也可以点击“保存草稿”。草稿仅当前提交人可见，刷新、切换页面或重新登录后可继续编辑。
6. 确认资料和说明后点击“提交验收”。提交时会固定所选资料版本，接替人随后进行验收；资料上传或关联本身不会自动通过验收。

若资料在草稿期间被撤销、过期，或你与接替人中任意一方失去访问权限，提交会被阻止，请替换资料或联系项目管理员。资料后来发布新版本不会自动覆盖已关联版本。单项已关联 10 份资料时，先移除不需要的资料再上传。

## 14. 系统设置与管理员首检

新环境建议按以下顺序检查：

1. **成员与权限**：创建成员、选择本人职能、分配最小必要角色、停用离开项目的成员。职能可在创建成员时从有效岗位模板中选择，也可在成员列表中直接调整，并作为离职登记的默认职能。
2. **LLM 配置**：填写 API 地址、模型和密钥，保存后执行真实连接测试。
3. **RAG 与知识存储**：确认服务状态不是仅由前端配置推断。
4. **飞书配置**：保存密钥、检测权限、验证事件通道和测试群。
5. **数据治理**：设置原始消息、访问审计、处理任务和备份保留策略。
6. **备份与恢复**：创建一致性备份，并在隔离环境执行恢复演练。
7. **运行监控**：查看接口、任务、飞书事件和 RAG 指标；样本不足时系统会显示“采集中”。

API Key、飞书密钥、`.env`、`config.json`、SQLite 数据库和邀请文件都属于本地敏感数据，不应提交 Git、放入知识库或通过普通群聊传播。

### 14.1 清空所有知识库数据

此操作仅限项目管理员，且必须先完成或取消进行中的处理任务。确认后会清空当前、待复审、已失效和已撤销的知识资产，以及关联原件、文档、索引、图谱、处理任务、知识任务、学习计划和交接记录；还会清空飞书已保存的历史消息、候选、飞书知识、诊断记录和资源文件。操作不会创建备份，不能从页面恢复。系统只保留不含正文的删除墓碑和安全审计，用于合规追溯，因此清空后的日常知识库与飞书内容中心应显示为空，不会继续展示“已撤销”或“已失效”资料。

飞书采集群、群级采集策略和来源权限属于配置，会被保留。清空后无需重新授权；后续新到达的授权群消息仍会按原有规则重新采集。

## 15. 三类常用工作方式

### 15.1 新项目建立知识基础

1. 管理员创建成员和来源权限。
2. 项目成员批量上传现有规范、需求、设计、风险和交接资料。
3. 知识运营检查处理任务和资产质量。
4. 发布可信资产并检查问答引用和图谱。
5. 项目经理建立岗位模板和新人计划。

### 15.2 每周知识运营

1. 查看飞书“需处理”和失败任务。
2. 处理待审核、待复审和投影异常资产。
3. 检查逾期知识任务并提醒责任人。
4. 运行 RAG 质量评测并分析负面反馈。
5. 检查备份、容量和运行告警。

### 15.3 人员离职或岗位接替

1. 发起离职交接并自动盘点知识。
2. 补齐资料、责任和风险。
3. 接替人验收并确认。
4. 自动生成接替人的学习计划。
5. 封存快照后停用离职成员，复审其负责的知识资产。

## 16. 常见问题排查

### 页面能打开，但数据一直加载不出来

- 确认地址是 `http://...`，不是 `file://...`。
- 刷新页面并重新登录，检查会话是否过期。
- 查看浏览器页面提示中的诊断编号。
- 到“处理任务”和“系统设置 / 运行监控”检查服务及数据库状态。
- 如果只是某些资产不可见，检查角色、项目关系和来源 ACL。

### 登录提示“账号尚未激活或已停用”

- 正式环境：联系管理员重新邀请、激活或恢复成员状态。
- 演示环境：确认 `.env` 已启用 `DEMO_SIMPLE_AUTH=true`，并确认该邮箱已经写入当前本地数据库。
- 修改 `.env` 后需重启服务。

### 测试连接成功，但没有填写 API Key

- 检查是否使用了不要求 Key 的本地 Ollama。
- 检查系统是否仍读取 `.env` 或本地 `config.json` 中已有的密钥。
- 正式验收应执行真实模型请求，不能只根据字段是否为空判断连接状态。

### 上传后知识库有资产，但问答或图谱没有数据

- 查看资产是否已生效，而不是草稿、待审核或处理失败。
- 查看处理任务中的向量、图谱和新人就绪度投影状态。
- 检查当前账号是否具备来源访问权限。
- 修复失败任务后再刷新业务页面。

### 飞书收不到消息或群聊

- 检查 App ID/Secret、机器人能力和事件通道状态。
- 检查应用是否已加入目标群，群是否显式授权给项目。
- 检查消息、资源下载、OCR 等权限是否已发布生效。
- 查看处理任务和飞书“需处理”，不要只看“已连接”标签。

### 图片或扫描 PDF 无法识别

- 安装 `backend/requirements-ocr.txt` 中的本地 OCR 依赖。
- 检查图片是否过大、模糊、旋转或文字过少。
- 检查飞书资源下载和 OCR 权限。
- 修复后从处理任务重试；不要重复上传同一原件。

### 多台电脑看到的数据不一致

当前为单机 SQLite 试点，业务数据保存在部署机器的 `data/app.db`，不会随 Git 自动同步。团队应访问同一个已部署服务，不要各自在本机启动独立数据库后期望数据自动合并。

## 17. 正确使用与安全边界

- 只上传当前项目有权处理的资料。
- 不把 API Key、App Secret、密码、令牌或邀请文件沉淀为知识。
- 对敏感来源设置明确 ACL，不以“管理员”代替来源授权。
- 重要回答必须查看引用；重要操作必须人工确认。
- 不用重复上传、重复建任务或关闭权限校验来掩盖失败。
- 撤销、删除、成员停用和交接封存前先确认影响范围。
- 定期备份 SQLite 和受控原件，并执行隔离恢复演练。
- 发现错误时保留任务 ID、资产 ID、发生时间和诊断编号，便于追踪。

## 18. 使用完成标准

一次完整、正确的知识沉淀至少满足：

- 来源和权限明确。
- 后台处理完成，失败项已处理。
- 资产处于正确生命周期状态。
- 预览内容准确，没有敏感信息泄露。
- 问答能够给出有效引用，知识不足时不会猜测。
- 图谱和新人赋能与当前有效知识一致。
- 发现的缺口形成责任明确、可验收的知识任务。
- 关键操作具有操作者、时间、原因和结果记录。

遇到无法自行处理的问题时，请向项目管理员提供页面名称、操作步骤、任务或资产 ID、发生时间和诊断编号，不要发送密钥、密码或完整敏感正文。
